VS Code Extension · NEXUS

One IDE. Three superpowers:
Orchestrate. Discuss. Reuse.

NEXUS is a chat-based AI coding agent that lives in your VS Code activity bar — but what makes it different is the team behind it. Spin up a swarm of sub-agents to tackle parallel jobs, host a live debate between expert personas before writing a line of code, and save your favourite expert configurations as reusable Skills. Everything else (tool-using chat, diffs, multi-model, history) is just the polish around those three.

01The Orchestrator — many agents, one job

The Orchestrator turns a single NEXUS chat tab into a conductor that breaks a big request into parallel sub-tasks, dispatches a fresh sub-agent to each one, runs up to four of them at the same time, and merges their reports into one coherent answer.

How to deploy DEPLOY

One click — no config, no flags.

  1. Open the Agent Chat view (NEXUS icon → first panel).
  2. At the top of the chat, find the tab strip. Next to the [+] "new chat" button you'll see [▣ DEPLOY]. Click it.
  3. A new tab opens labelled Orchestrate. Its agent has access to a special delegate_task tool that the regular chat does not.
  4. Describe your overall job in plain English. Examples:
    • "Audit every file in src/ for unhandled promise rejections."
    • "Write Jest tests for auth, cache, db, logger, and router in parallel."
    • "Refactor each of these three React components to use hooks — one sub-agent per component."
  5. Watch the orchestrator decompose the request and dispatch sub-agents. Each one shows a live progress panel; the conductor synthesises the final answer when they finish.
When to use it Reach for the orchestrator whenever the work is naturally parallel — N independent files, N test suites, N PRs, N audit targets. For a single-file fix or a quick question, a regular chat tab is faster.

02The Discuss tab — let experts argue first

Discuss is a multi-agent debate room. Drop a problem in, pick the roles you want at the table (planner, coder, reviewer, researcher), and watch them argue over the solution in their own swim-lanes for several rounds. When they converge, NEXUS captures the agreed plan — and you can hand it straight to the chat agent to execute.

How to use the Discuss tab RUN

For the hard, ambiguous problems where one agent isn't enough.

  1. Open the NEXUS activity-bar icon and select the Discuss view (the second panel).
  2. In the PROBLEM textarea, describe what you want the team to figure out. Discuss is for design questions, trade-off calls, and "which approach is best" debates — not single-shot fixes.
  3. Pick a MODEL for the debaters and set ROUNDS (1–12; default 4). More rounds = deeper debate, more tokens.
  4. Tick which AGENTS you want at the table:
    • planner — proposes architecture & sequencing
    • coder — focuses on concrete implementation
    • reviewer — pokes holes, finds edge cases
    • researcher — pulls in references & precedent
  5. Click [RUN]. Each agent gets its own live lane; a director log up top tracks who's speaking and why. You can interject at any time via the "direct the agents live…" input at the bottom — anything you type there is injected into every agent's next turn.
  6. When the debate converges, a final consolidated solution appears at the bottom — the plan they all agreed on.
  7. Hit Execute Plan to hand that plan straight to the main Agent Chat, which will then actually carry it out (write files, run commands). One smooth handoff: debate → decision → execution.
Pro tip — direct the conversation live Don't passively watch. Use the live chat bar to steer them: "ignore the legacy migration", "stay in TypeScript", "the reviewer should focus on perf, not style". Your messages reach every agent's next turn.
Discuss vs Orchestrator Discuss = many agents arguing about what to build (one shared problem, many opinions). Orchestrator = many agents building different parts of an already-decided plan in parallel. They compose beautifully: Discuss to decide, Orchestrator to execute.

03Skills — your library of personal experts

A Skill is a saved system-prompt preset — a way to spin up a chat that is already configured as a specific kind of assistant. Strict code reviewer. Test writer for your framework. SQL tuner. Doc generator. Build one once, reach for it forever.

How to use Skills USE

Right there in the activity bar — the third panel under the NEXUS icon.

Launching a skill

  1. Open the Skills tree (NEXUS icon → third panel). You'll see two groups: system skills (bundled, read-only) and your skills.
  2. Hover any skill — three inline buttons appear:
    • ▶ Use Skill in NEXUS — copies the skill's prefix to your clipboard, ready to paste into any chat.
    • 💬 Chat with Skill — opens a brand-new Agent Chat tab already loaded with the skill's instructions. Just start typing.
    • ↪ Open Skill — reveal the skill file in the editor.
  3. Right-click any of your skills for Customize (edit prompt & metadata) or Delete. System skills can be opened and used but not modified.

Creating your own

  1. In the Skills tree title bar, click the + New Skill button.
  2. Fill in a name, a display title, a one-line description, and the system prompt that defines the skill's behaviour.
  3. Save. The new skill appears under your skills immediately and is available in Chat with Skill straight away.
Skills compose with the orchestrator Launch an orchestrator session and reference your saved skills in the prompt ("Delegate to a sub-agent using the Strict Reviewer skill") — the orchestrator will pick them up and apply them to its sub-agents.

Skills live on disk under ~/.config/qgenie-cli/agent/skills/, so you can version them with your dotfiles.

04Quick start (everything else)

  1. Click the NEXUS icon in the VS Code activity bar.
  2. If prompted, run NEXUS: Update API Key from the command palette and paste your QGenie key.
  3. Pick a model from the dropdown at the top of the chat (Claude is the default).
  4. Type a request and hit Enter. When NEXUS proposes an edit, review the live side-by-side diff and click Approve or Deny.

06Safety & control

NEXUS will never modify a file, run a shell command, or delete anything without showing you first and waiting for your approval. Read-only actions run silently so the agent can keep moving — but anything that changes your machine pauses for your OK.

If something goes wrong Click Deny on any approval prompt to cancel that single action. To stop a runaway chat turn, hit the Stop button at the bottom of the chat. To stop a Discuss debate, hit [STOP] in the Discuss panel.
⚡ New — local search

07The Codebase Indexer — local, AI-free code search

Before the agent reads a single file, it can ask a local index of your repository where the relevant code lives. The index is built entirely on your machine — no AI, no embeddings, no network calls — using fast BM25 lexical search plus a ranked symbol outline (a "repo map"). The agent gets just the snippets it needs instead of whole files, which cuts token cost by roughly 10–100× and makes every answer faster and cheaper.

Build the index INDEX

One click. It runs locally, yields periodically so VS Code stays responsive, and is cached so re-indexing only touches files that actually changed.

  1. Click the [▣ Index Codebase] button in the status bar — or run NEXUS: Index Codebase from the Command Palette.
  2. The button updates to ✓ Index up to date (N), showing how many files are indexed.
  3. That's it — the agent now sees the index and will automatically search it first when exploring your code.
Stays out of your way A file watcher quietly notices when files change and flips the button to ↻ Re-index (N changed). It never rebuilds on its own — you click when you want a refresh, and only the changed files are re-read.

What gets indexed

Searchable chunks

Your source is split into overlapping windows tagged by kind — function, class, method, interface — so matches land on real code, not noise.

Ranked symbol map

A "repo map" outline of your functions and classes, ranked by how often they're referenced, so the most important symbols surface first.

Live freshness

Tracks file count, chunk and symbol counts, and when it was last built — and marks itself stale the moment files change.

Stored locally

Everything lives in a plain JSON file under .nexus/index/ in your workspace. Nothing leaves your machine.

Commands & controls

  • NEXUS: Index Codebase — build (or incrementally update) the index.
  • NEXUS: Re-index Codebase — force a full rebuild, ignoring the cache.
  • NEXUS: Clear Codebase Index — delete the index entirely.
  • NEXUS: Search Codebase (local index) — run a query yourself and inspect the hits.
How the agent uses it When an index exists, search_codebase is the agent's preferred first step for exploring unfamiliar code: it returns the repo map plus the top-ranked snippets (with file:line references) instead of dumping whole files. If the agent tries to read a file before searching, NEXUS nudges it to query the index first. No index yet? The agent simply falls back to ordinary file search.

Indexing covers common source languages (C/C++, TypeScript/JavaScript, Python, Rust, Go, Java, and more) and skips build output, node_modules, binaries, minified bundles, and very large files automatically.
